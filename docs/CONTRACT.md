# API contract — indicators JSON

Two read modes expose the **same model**:

1. **FastAPI** (`src/api/main.py`), read-only SQLite, OpenAPI at `/docs`.
2. **Static contract** generated by `scripts/build_pages.py` and published on
   GitHub Pages under `/api/v1/`.

Base URLs:

```
FastAPI:  http://127.0.0.1:8000/api/v1        (local)  or your deployment
Pages:    https://<user>.github.io/<repo>/api/v1
```

## Common reading object

Every reading (latest, history item) has these fields:

| Field | Type | Notes |
|---|---|---|
| `slug` | string | indicator id, e.g. `ibr_overnight` |
| `date` | `YYYY-MM-DD` | run date in America/Bogota |
| `value` | number | normalized REAL; IBR = **nominal** series |
| `value_published` | number \| null | reference value as published (IBR = effective `% E.A.`) |
| `unit` | string | canonical unit from the catalog, e.g. `COP`, `% nominal anual` |
| `unit_as_published` | string | unit text as shown by the source (`DÓLARES / BARRIL`, `Valores en EUR`, `%`, …) |
| `status` | `ok` \| `forward_filled` \| `manual` | reading status |
| `base_gap` | boolean | true when the variation base is not the natural previous day |
| `source_date` | `YYYY-MM-DD` \| null | date shown by the source (best effort) |
| `variation_pct` | number \| null | `(v_today - v_base) / v_base * 100`; null on no base or division by zero |

Variation semantics: base is the previous natural day when a reading exists;
otherwise the most recent reading within `max_gap_days` (7) with
`base_gap = true`; no reading → `variation_pct = null`.

## Static files

| File | Content |
|---|---|
| `v1/indicators.json` | catalog: `generated_at` + `indicators[]` with `slug`, `source_url`, `visible_label`, `unit`, `latest` |
| `v1/latest.json` | `generated_at` + `indicators` object keyed by slug → reading |
| `v1/indicators/<slug>/latest.json` | reading or `{}` when no readings exist |
| `v1/indicators/<slug>/history.json` | `slug`, `unit`, `from_date`, `to_date`, `readings[]` (31-day window) |
| `v1/indicators/<slug>/variation.json` | `slug`, `date`, `value`, `previous_date`, `previous_value`, `variation_pct`, `base_gap` |

### Example — `v1/indicators/ibr_overnight/latest.json`

```json
{
  "slug": "ibr_overnight",
  "date": "2026-10-08",
  "value": 11.407,
  "value_published": 12.259,
  "unit": "% nominal anual",
  "unit_as_published": "%",
  "status": "ok",
  "base_gap": false,
  "source_date": "2026-10-08",
  "variation_pct": -0.0351
}
```

## FastAPI endpoints

| Method | Path | Response |
|---|---|---|
| GET | `/api/v1/indicators` | `IndicatorsResponse` (catalog + latest per indicator) |
| GET | `/api/v1/indicators/{slug}/latest` | reading object (404 if unknown/empty) |
| GET | `/api/v1/indicators/{slug}/history?from=&to=` | `HistoryResponse` |
| GET | `/api/v1/indicators/{slug}/variation` | `VariationResponse` |
| GET | `/docs` | Swagger UI with real-data examples (2026-10-08 run) |
| GET | `/openapi.json` | OpenAPI 3.1 schema |

## Headers and caching

- **CORS:** FastAPI sets `Access-Control-Allow-Origin: *`. GitHub Pages serves
  the static JSON with the headers GitHub provides; custom `Cache-Control` /
  CORS headers cannot be configured on Pages. If you need guaranteed
  `Cache-Control: no-cache`, use the FastAPI mode behind your own proxy.
- The FastAPI SQLite connection is opened with `mode=ro` (read-only URI).

## Statuses and reliability

- `status='ok'`: fresh extraction.
- `status='forward_filled'`: the source failed; the last stored reading was
  copied and `reason` explains why. If there is no previous reading, the
  indicator is absent for that day (never invented).
- `status='manual'`: reserved for owner-entered corrections.
- Out-of-`plausible_range` values are treated as parse failures
  (forward-fill + Healthchecks `/fail` ping).
